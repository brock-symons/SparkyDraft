session. `CLAUDE.md` (committed) stays the authoritative living map;
this file is denser and file-by-file.

Synced against `origin/main` at commit `20841f7` (2026-09-08, right after

## app/src/core/

- **catalog.js** — Exports `SYMBOL_LIBRARY`, `LAYER_DEFS`, `CABLE_SIZES`, `PROTECTION_LIBRARY`, `CATEGORY_LABELS`, `CATEGORY_ORDER`. Extracted verbatim from the legacy app; drives the whole device catalog (colors, costs, labour hours, watts, cable/protection defaults) that feeds quoting and load estimates. Gotcha: must be re-extracted, not hand-edited, and changes require re-running `quote-parity.mjs`/`panel-schedule-parity.mjs`.
- **circuits.js** — Circuit record shape (`makeCircuit`), `devicesOnCircuit`, `findBoardObjects`, and the degree-constrained nearest-neighbour tree `computeChainEdges`/`computeGpoChains` that derives (never stores) branching power-circuit runs from device positions. Depends on `switching.js` for hard-active switch detection.
- **civil.js** — Civil/underground plan model: `makeCivilPlan`, `currentCivilPlan`/`currentPlan`, object constructors (`makePit`, `makeBuildingEntry`, `makePole`, `makeConduit`, `makeOverheadRun`), takeoff/quoting (`computeAllCivilTotals`, `buildCivilSchedule` — deliberately preserves a production quirk where comms conduit/poles/overhead are excluded from the whole-job total), civil snapping (`snapPointCivil`), hit-testing per entity type, and legend building (`computeCivilLegendEntries`). Imports from `civilCatalog.js`.
- **civilCatalog.js** — Verbatim-extracted civil libraries: `PIT_LIBRARY`, `CONDUIT_SIZES`, `COMMS_CONDUIT_SIZES` (separate table from electrical, NBN sizes), `BUILDING_ENTRY_SERVICE_TYPES`, `PIT_SERVICE_TYPES`, `POLE_LIBRARY`, `OVERHEAD_CONDUCTOR_SIZES`. Re-extract rather than edit; guarded by `civil-parity.mjs`.
- **civilRenderer.js** — `renderCivilScene()` and drawing helpers for the civil canvas: conduit/overhead polylines colour-coded by size table, filled vs. hollow poles (private vs. network-owned), rotated-square building entries, draft/ghost previews. Deliberately a separate render pass from the electrical `renderer.js`, sharing only plan-agnostic helpers (grid, dimensions, snap).
- **cloud.js** — Every Supabase call (auth, orgs, members, invites, personal/shared projects, per-project access, problem reports), ported call-for-call from production. Holds a snapshot+subscribe store (`getCloudState`/`subscribeCloud`) instead of production's module-level `let`s. Exports config constants `SUPABASE_URL`/`SUPABASE_ANON_KEY` and `cloudConfigured`. Functions return `{ok, error}` rather than toasting directly.
- **cloudFormat.js** — `toCloudRecord`/`fromCloudRecord`: the ONE place converting between the redesign's project model and the shared Supabase `data` jsonb column, which must keep PRODUCTION's field shape since both apps can write it. Preserves unknown fields via `__extras`, narrows rate fields string→number (documented deviation), rebuilds `nextId` defensively. Load-bearing — do not "simplify."
- **commands.js** — `createCommandRegistry()`: single source of truth for every invokable action (id, title, shortcut, `when`, `run`), feeding the palette, keyboard layer, toolbar and context menu so they can't drift apart (a documented former production bug). Also exports `formatShortcut`, `matchesShortcut`, `isTypingTarget`.
- **comms.js** — Comms racks/ports model: fixed numbered ports per rack (`defaultCommsPorts`, `DEFAULT_COMMS_PORT_COUNT=24`), derived patch-panel unit count (`patchPanelUnitsForRack`), port assignment (`assignDeviceToPort`), and `migrateLegacyCommsData()` — data-integrity-critical migration converting old `kind:'data'` circuits into rack ports, run before anything else reads a loaded project.
- **controller.js** (2300+ lines) — `createController()`: the interaction/gesture layer owning transient (non-document) state — tool, selection, hover, snap, marquee, drag gestures, civil-mode sub-state. All document mutations go through `doc.commit(...)`. Handles pointer down/move/up for both electrical and civil modes, linear-primitive drawing (cable/wall/dimension), switch linking, circuit/comms/quote mutation functions, alignment/distribution, civil entity placement/dragging/vertex editing. Also owns `toggleLayerVisibility`/`isLayerHidden` (viewer-local override pattern, new as of PR #17) and `assignCircuit` (multi-select bulk circuit assignment, new as of PR #17). The largest and most central file in `core/`.
- **document.js** — `createDocument()`: timeline-based undo/redo (`commit`/`undo`/`redo`/`jumpTo`/`history`) with a single commit funnel and a `readOnly` gate enforced here (viewer mode). `emptyProject()`/`makeFloor()` define the project data model (floors, civilPlans, circuits, elevations, layers, custom symbols, quote settings). `makeFloor()`'s `snapEnabled` now defaults `false` (changed this session — was `true`). `migrateLoadedProject()` runs `migrateFlatDrawing()` then `migrateLegacyCommsData()` in order. `findDuplicateDevices()` and `allObjects()` are project-wide helpers.
- **elevations.js** — Elevation model (`makeElevation`, `makeElevationItem`, `activeElevation`) and layout math (`elevationLayout`, `elevationItemPoint`) ported verbatim from production's non-interactive `#elevCanvas` — deliberately a report-style dialog, not a third plan/drafting type (per owner-review resolution documented at length).
- **geometry.js** — Pure coordinate/hit-testing math: `worldToScreen`/`screenToWorld`, `hitTestObjects`, `distToSegment`/`hitTestSegments`, `objectsInRect`, `boundsOf`, `viewForBounds`, `zoomAt`, plus scale semantics (`worldToMetres`, `metresToWorld`, `formatDistance`, `gridWorldUnits`) — scale is world-units-per-metre, matching production exactly.
- **legend.js** — `computeLegendEntries()`: per-floor tally grouped by device+switch-gang, sorted by plain `localeCompare` (a deliberately preserved production quirk, not `CATEGORY_ORDER`), feeding both the Layers panel and print/PDF export.
- **panelSchedule.js** — Highest business-logic-risk file: diversity/demand estimate (`classifyCircuitDiversity`, `diversifiedWatts` — a documented non-AS/NZS-3000 simplified estimate), `effectiveWatts`/`deviceHeightMm`, `estimateCircuitCableLength` (hard-active runs only, by owner instruction not to extend speculatively), `buildPanelScheduleData`, and `panelScheduleText` export. Ported verbatim, parity-tested.
- **persistence.js** — Local (browser) save/load under the `sparkydraft_cad:` namespace (deliberately separate from production's `project:` keys), `SaveState` enum, and per-device workspace-UI persistence (`loadWorkspaceUI`/`saveWorkspaceUI`). Cloud/Supabase sync intentionally not touched here.
- **print.js** — Offscreen-canvas print/PDF pipeline: `buildPrintPages()` builds the same `printPagesData` shape as production for both the on-screen review and jsPDF export (`drawPdfPage`), using `renderScene`/`renderCivilScene` with a `printMode` flag rather than a parallel renderer. Also `hexToRgb`, `fileSafeName`/`jsonFileName` (deliberately different sanitizer conventions, matching production's two different call sites).
- **quote.js** — Quote totals (`computeQuote`) in production's exact order of operations (materials→labour→protection→subtotal→margin→GST, where GST compounds on margin), `effectivePrice`/`effectiveLabour`/`effectiveProtectionCost` (per-object overrides), `quoteLines` (itemised vs. summary), `quoteText` export. Ported verbatim, parity-tested; `GST_RATE=0.1` is a literal flagged for owner review.
- **renderer.js** — `renderScene()`: the main electrical canvas full-repaint renderer (dark CAD palette `PAINT`), viewport-culled, drawing plan image → grid/origin → walls → cables → switch/circuit/comms runs → devices → circuit labels → dimensions → draft/selection/snap/marquee/measure overlays. Also owns plan-image decode caching (`getPlanImage`) and device radius/label drawing logic. Currently draws every device category as the same circle shape — see the symbol-distinguishability research doc for the open gap here.
- **snapping.js** — `snapPoint()`: pure port of production's snap precedence (device centre → wall projection → axis-align to devices → grid), returning `{point, guides, target, reason}` so the UI can explain why something snapped (an intentional improvement over production's silent snapping).
- **switching.js** — Switch-link/lighting-bank model: `SWITCH_IDS`/`LIGHT_IDS`, `linksForSwitch`/`linksForLight`/`groupsForSwitch`, gang-count logic (`recomputeSwitchGang` — only ever raises), `autoGroupForSwitchLink`, `bankDisplayName`, and the derived (never-stored) physical wiring: `computeLightingBanks`, `computeChainOrder`, `computeBankAttachPoints`, `propagateSwitchCircuitToLinkedLights`, `removeLinksForObjects`.
- **symbols.js** — Symbol resolution: `resolveSymbol(project, id)` merges shipped catalog + project's `customSymbols` + project's `priceList` overrides into one answer, avoiding the "custom fitting renders as '?' " bug found once already. `allSymbols()` and `makeSymbolResolver()` are the shared entry points used everywhere.

## app/src/ui/

- **CanvasStage.jsx** — The React↔canvas boundary. Repaints batched into one `requestAnimationFrame`; scene state read from refs at paint time so dragging never triggers a React re-render. Dispatches to `renderScene`/`renderCivilScene` depending on mode, and binds pointer/wheel/contextmenu events natively (not via React props) for reliable pointer capture.
- **Cloud.jsx** — All cloud-related UI: `AuthGate`/`GateForm` (six gate modes), `AccountDialog`, `InviteBanner`, `OrgDialog`/`InvitesTab`/`OrgsTab`, `ProjectAccessDialog`, `ReadOnlyBanner`, `ReportProblemDialog`. Explicitly documented as JSX-not-innerHTML for XSS safety (the flagged production vulnerability class). Exports `useCloud()` hook (`useSyncExternalStore` over `core/cloud.js`).
- **CommandPalette.jsx** — Ctrl/Cmd+K palette reading straight from the command registry (`registry.search`), grouped results, arrow-key navigation, Escape-to-close at the document level.
- **ContextMenu.jsx** — `CanvasContextMenu`: right-click menu whose items are command IDs resolved through the registry (`itemsFor()` picks a fixed list per selection state), so it can't drift from palette/shortcuts.
- **Inspector.jsx** (~1500 lines) — The contextual properties panel with four states: `DrawingProperties` (nothing selected — contents, floor plan [empty-state hint now reads "Import floor plan…"], rooms, grid/snap, display), `DeviceProperties`/`SwitchingSection` (one device), `MultiProperties` (align/distribute/bulk circuit assignment via `controller.assignCircuit`, new as of PR #17), `CivilProperties` (civil entity of 5 kinds — pit now has a Service row using `PIT_SERVICE_TYPES`, new as of PR #17/#18), `SegmentProperties` (cable/wall/dimension), `ToolContext` (an armed tool). `inspectorTitle()` computes the dynamic panel title.
- **Panels.jsx** (~1050 lines) — `LibraryPanel` (searchable device catalog with favourites/recent/custom), `LayersPanel` (visibility/lock toggles + legend + circuit/switch-run display toggles — visibility toggle now routes through `controller.toggleLayerVisibility()`/`isLayerHidden()` so a read-only viewer gets a local-only override, new as of this session), `CircuitsPanel`, `CommsPanel` (rack/port management incl. legacy-recovered ports), `CivilPalette` (civil tool/type selection — choosing arms a tool), `CivilPlansPanel` (multi-site-plan management).
- **ProjectPicker.jsx** — The project browser: merges local + cloud rows (cloud is source of truth once signed in, local only shown if not already in cloud), an org-shared tab, delete/share actions, `InviteBanner` integration, account/org dialogs.
- **Workspace.jsx** (~920 lines) — The application shell: header (project name, save indicator, floor↔civil segmented control, undo/redo, palette button), `ToolRail`/`MobileBar` (electrical-mode rail order is now Place a device → Circuits → Comms rack → Layers, reordered this session; civil-mode's rail untouched), `Dock`/`Sheet` (desktop-docked vs. mobile-overlay panels), `StatusBar`, `ZoomCluster`, `ModeHint`/`EmptyCanvasHint` overlays.
- **primitives.jsx** — Shared design-system components: `Button`, `IconButton`, `Tooltip`, `TextInput`, `NumberInput` (commits on blur/Enter, not per-keystroke), `Select`, `Toggle`, `Section` (collapsible), `Dialog` (focus-trapping modal), `ToastHost`/`useToasts`, `EmptyState`/`ErrorState`/`Spinner`, `useElementSize`/`useBreakpoint` hooks.

## app/src/main.jsx (~3700 lines)

Application root. `WorkspaceRoot` wires together: the document (`createDocument`), the interaction controller, the command registry (~60 commands, including `circuit: true` sections-visibility flag), keyboard shortcut layer, autosave (debounced, piggybacking cloud sync), workspace-UI persistence, and view/viewport management (`fit()`, `zoomToSelection()`). Also defines every report/dialog component not delegated to `ui/`: `HistoryDialog`, `AssignCircuitDialog`/`AssignRoomDialog`, `DuplicatesDialog`, `CivilMaterialsDialog`, `ElevationCanvas`+`ElevationsDialog`, `PrintExportDialog`+`PrintPage`, `QuoteDialog`, `PriceListDialog`, `PanelScheduleDialog`, `ExportTextDialog`, `CircuitDialog`, `RoomDialog`, `CustomFittingDialog`, `CalibrateDialog`, `ErrorBoundary`. `App()` at the bottom decides between `AuthGate`/`ProjectPicker`/`WorkspaceRoot` based on cloud auth state and the `open` project descriptor.

## index.html (repo root)

Bootstrap for the live app: Tailwind CDN + design tokens inline, then an in-browser Babel module loader that fetches/transforms/caches `app/src/main.jsx` and its dependency graph as blob URLs. Documented temporary tech debt. Must be served over `http://`.

## legacy-index.html (retired, ~9180 lines)

Original single-file vanilla-JS app. One global `state`, ~240 top-level functions. Kept only as (a) the parity tests' ground truth (functions extracted by name at runtime) and (b) historical/rollback reference — not a second live app. This is where the flagged unescaped-`innerHTML` XSS pattern lives (e.g. `renderOrgInviteBanner`); `ui/Cloud.jsx` is the live app's documented replacement. Its `--hud-*` CSS convention and `.hidden-feature` convention are both referenced elsewhere in the repo as intentional, preserved patterns.
